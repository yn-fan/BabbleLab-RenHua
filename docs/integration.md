# 整合决策

首版以 `lieflat-less-ai-tone@fe13f1a0712cd2c138b6cdc500a77927d5bf04ec` 和 `humanizer@0ef9fe5bc3572734fd3ae6c448fe00a30cd5dcf0` 为基线。上游随时可能更新，本页只解释这个固定版本的取舍。

## 范围

交付一个名为 `babblelab-renhua` 的技能，中文为主，英文按需加载。它是编辑工作流与本地辅助工具，不是自动识别 AI 作者的分类器，也没有自己的模型服务。

## 冲突如何处理

| 问题 | 上游情况 | RenHua 决定 |
|---|---|---|
| 是否每次报告后等确认 | lieflat 默认先报告并暂停；humanizer 直接编辑 | 按用户请求路由。已授权改写就做完；“先诊断”只诊断 |
| 是否调整文章结构 | lieflat 默认锁定；humanizer 允许改段与重组 | 默认保守；用户要求深度改写才重组 |
| “不是 A 而是 B” | 两者都高度关注，某些示例删掉负命题 | 先判断真实否定、对比是否有信息；保留两侧主张 |
| 句长与段长 | lieflat 文档对句长证据有不一致表述；humanizer 建议长短交替 | 不设节奏目标；只处理可解释的阅读问题 |
| 破折号、引号、三项并列 | 英文规则强度较高；中文研究里有模型差异 | 按语言、体裁、作者样稿判断，不机械禁用 |
| 词表 | humanizer 提供常见词；lieflat 部分词表证据被后续研究否决 | 词语本身不构成错误；术语与准确表达保留 |
| 增添个性 | humanizer 允许在适当文风中补反应 | 保留已有个性；不代作者编经历、情绪或意见 |
| 示例的事实来源 | 个别上游示例新增细节或丢掉范围信息 | 使用原创示例，逐项检查信息守恒 |
| 检测结果 | 上游有 A/B/C/F/H/X 分类与研究参考值 | 原始数据可追溯；界面只称候选与统计，不推导身份、模型指纹或质量总分 |
| 交付形式 | humanizer 粘贴模式输出草稿、问题、最终稿 | 默认一份最终稿，诊断或对照按需提供 |

## 重用与重写的边界

只原样分发 lieflat 的 `scripts/detect.py` 及其 LICENSE。检测函数经新入口调用；旧命令行的字数拒绝策略、参考值解读和强制暂停工作流不作为 RenHua 的用户入口。

humanizer 的 26 类模式经过归并、中文适配和条件化处理，保留 MIT 声明。我们不复制它的原文示例，也不把 Wikipedia 页面收录为本项目文件。humanizer 自述其经验参考了 Wikipedia 的 “Signs of AI writing”，该背景链接见来源文件。

新写的主技能、规则说明、命令入口、安装器与示例按融合仓库的 CC BY-NC 4.0 许可提供。完整来源、作者、许可证和文件校验值随技能安装包携带。

## 证据边界

lieflat 的语料规模、显著性与模型比较是上游自述；本项目没有取得并独立复现那套完整研究。保留检测代码不代表认可每项统计解释。测试验证文件处理与交付边界，文风改进仍需要实际阅读评审。
